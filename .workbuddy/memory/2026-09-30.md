### 为什么 `fixed` 而不是 `sticky`

`sticky` 要求元素仍在文档流里 → 必须占一列 → 容器必须变宽 → 又回到两档宽度。
`fixed` 让 `<aside>` 彻底脱流，不进网格、不占正文宽度，页面永远单列 44rem。

### ⚠️ 最大的坑：`offsetParent` 在 fixed 元素上恒为 null

## 宽度调整：44rem → 50rem；目录从 fixed 改回 sticky（20:10–21:00）

### 起因一：风息说「视觉上太窄了」

44rem 是照抄旧列表页宽度来的，**从来没论证过「一行几个字读起来舒服」**。量了一下：
容器 704px − 内边距 40px = 正文 664px ÷ 17px ≈ **39 个汉字/行**。

顺带发现我上一轮的解释不完整：改版前后**文字宽度几乎没变**（672px → 664px，差 8px），
真正变的是**外壳**（992px → 704px），宽屏下两边空出来的留白一下子多了一大片。
风息感觉到的「窄」主要来自留白，不是行宽。

他选了 **50rem** → 容器 800px / 正文 760px ≈ **44 个汉字/行**。

### 起因二：目录压住了页头

「目录和顶部导航平齐了，压住了分割线」—— 这是 `position: fixed` 的必然结果：
它相对**视口**定位，`top: 2.5rem` 让它和页头齐平、正好压在 `.site-header` 的 `border-bottom` 上。
**教训：「浮在留白里」≠「相对视口定位」。**

### 两个改动

**1. 宽度提成一个变量**，否则目录位置和断点会在多处跟它脱节：

```css
:root { --container-size: 50rem; }          /* 唯一开关 */
.layout-narrow .container { max-width: var(--container-size); }
```

⚠️ **顺带修一个会吃掉加宽的坑**：`.post-layout` 的网格轨道原本是
`minmax(0, min(42rem, 100%))`。42rem = 672px 是「容器比正文宽」时代的残留，
以前恒被 100% 压住所以看不出来；容器到 50rem（内容 760px）之后它**真的生效**，
会把正文重新卡回 672px。已改成 `minmax(0, 100%)`。

**2. 目录：`fixed` → 「`.post-layout` 自己溢出一列 + `sticky`」**

```css
.post-toc { display: none; }

@media (min-width: 80rem) {
  .post-layout--with-toc {
    width: calc(100% + 15.5rem);              /* 目录 14rem + 间距 1.5rem */
    grid-template-columns: minmax(0, 1fr) 14rem;
    gap: 1.5rem;
    align-items: start;                        /* 不然网格项被拉伸，sticky 没余量可动 */
  }
  .post-toc { display: block; position: sticky; top: 2rem;
              max-height: calc(100vh - 4rem); overflow-y: auto; }
  .post-toc-inline { display: none; }
}
```

**关键点：溢出的只有 `.post-layout` 这一个盒子**，`main.container` 仍是 `--container-size`，
所以页头 / 页脚宽度不受影响，正文列稳稳定在 760px、与页头左右边缘严格对齐。
目录留在文章自己的流里 → 从**与文章标题同高**开始，滚动时才钉住，够不着页头。

**断点手算**（媒体查询读不了 CSS 变量）：
`50rem/2 − 1.25rem(内边距) + 15.5rem(溢出) = 39.25rem ≤ 50%` → 视口 ≥ 78.5rem
→ 取 **80rem（1280px）**，临界点留 1.5rem 余量。改宽度/目录宽/间距都要重算。

| 1296 / 1400 / 1600 | 同上，只是居中位置平移 | `sticky`，右边缘距窗口 28 / 60 / 172px |

## 后台「看起来没样式」的真凶：Hono JSX 转义 `<style>` 内容

- 风息问后台是不是裸 HTML。后台其实一直有内联极简样式（§11：无单独构建链），但 `layout.tsx` 用 `<style>{STYLE}</style>` 写法，**Hono JSX 会把字符串子节点转义**：`"PingFang SC"` 变成 `&quot;…`，而 `<style>` 是 raw text 元素、浏览器不还原实体 → `font-family` 声明整条失效 → 正文落回默认衬线字体，观感=裸 HTML（布局样式其实都在）。
- 修复：`<style dangerouslySetInnerHTML={{ __html: STYLE }} />`（两处：AdminLayout / PlainLayout）。STYLE 是文件内写死常量、无用户内容，安全；文件头注释更新了纪律说明（业务视图仍禁用 dangerouslySetInnerHTML）。
