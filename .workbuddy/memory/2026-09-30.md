## 导航/版式改版 + 删除路径修复（第二轮）

风息先问了两件事：为什么动不动全站重渲、发一篇文章牵连的分页/分类/标签页能不能避免。
量完之后的结论：**800 级重渲只由「改主题样式」触发**（指纹变 → 每个 HTML 的 `<link>` 变），
写文章只动 30~40 个对象。真正的浪费在删除路径。

### 改了什么

**全站零侧栏**（`theme/components/sidebar.ts` 删除）

- 导航收进顶栏：`首页 / 分类 / 标签 / 归档 / 关于`，不做下拉展开
- 新增索引页 `/categories/`、`/tags/`、`/archives/` → `theme/overview.ts`（新 URL，进 sitemap，不分页）
- 「关于」链到独立页面 `about`（`render.ts` 的 `ABOUT_SLUG`，线上确实有 cid=2 slug=about）
- 动机不是审美：侧栏带**全局可变数据**（计数、最新文章），挂在文章页上意味着
  「发一篇理论上要失效 765 个页面」。去掉后可变数据只活在 3 个索引页对象里

**容器宽度分档**：`.layout-narrow` 44rem（列表类页面）/ `.layout-post` 62rem（文章页），由 `layout.ts` 的 `width` 选项 → body 类

**文章目录**：`theme/toc.ts` 服务端抽 h2/h3、生成锚点 id 并写回正文（中文标题直接用汉字做 id，重名 `-2` 去重）。
HTML 里故意两份（宽屏 `<aside>` sticky / 窄屏 `<details>`），CSS 按 62rem 二选一，零 JS。
滚动高亮加在 `app.js`（只处理宽屏那份）。

**删除路径**：`deletePost` 从 `siteTargets()`（全站 800）改成 `postDeleteTargets()`（约 35）。

- 本地 e2e **139 项全过**（121 → 139，新增 18 项：索引页、顶栏、无侧栏、TOC、删除范围）
- 线上数据核对：111 篇可见 + 5 页面 + 36 hidden、7 分类、198 个有文章的标签（共 274）、58 个月 →
  全站 **803** 个对象（改版前 800，+3 个索引页）
- 本地导出 R2 对象起静态服务，用系统 Chrome 实测 1280/390 两个断点 + 亮暗：
  列表容器 704、文章列 672、目录在正文右侧、窄屏右栏目录隐藏且 `<details>` 可用、滚动高亮跟得上

### 量出来的两个真实缺陷（已修）

1. **`.post-body` 上的 `margin-inline: auto` 在 CSS Grid 里会退化**：grid item 带 auto 外边距会放弃
   stretch、变成内容宽度 → 42rem 的正文列实际只有 340px，而 computed `max-width` 依然是 672px。
   修法：列宽交给网格轨道（`minmax(0, min(42rem, 100%))`），元素上不写外边距。
2. **「无目录」模板分支漏了 `.post-body` 包裹** → `/about.html` 这类页面正文铺满 62rem。

两条都是「模板和 CSS 看着对、截图也看不出、只有量 `getBoundingClientRect` 才暴露」。
